# Kimi adversarial review disposition

Updated through all 20 completed safe-packet rounds plus the final local verification pass. Kimi was intentionally not given source code, local paths,
credentials, or photos, so “evidence missing” findings are not automatically treated as product
defects. Each finding is resolved against local source and executable checks.

## Round 5 local adjudication

- **Candidate token resurrection (P1-2): fixed.** A separate Room `suppressed_photos` table records the stable local photo identifier before the indexed row is marked. `clearIndex()` deletes candidates but deliberately preserves this table; MediaStore scans and picker imports consult it before creating a candidate. The API 34 persistence device test passes.
- **Malformed JPEG / extended APP0 (P0-4, P1-1, P2-3): fixed at the parser boundary.** Fresh Android encoder output is structurally stripped of APP0-APP15 and COM before SOS, then fully parsed with bounds, scan and exact-EOI checks. Seven JVM cases and the real Bitmap/EXIF/GPS device test pass.
- **OSS lifecycle drift (P1-4): fixed for new uploads.** The backend revalidates the bucket lifecycle before every upload target, in addition to startup validation and immediate/periodic deletion. Real OSS proof remains external.
- **Upload URL variants (P0-7): direct OSS branch removed.** Exact host/scheme/port/userinfo, suffix, Unicode, query, fragment and traversal variants are rejected; only the API same-origin UUID session path is accepted and receives the bearer.
- **Cost reset on bearer rotation (P0-8): rejected as inaccurate for hard caps.** Daily/monthly counts and ownership are keyed by stable server device ID, not bearer hash. The bearer hash is only the minute-level limiter; unauthenticated registration is separately IP-rate-limited. Real deployment load proof remains external.
- **External evidence findings (remaining P0/P1): accepted.** Physical OEM devices, the authorized privacy set, hosted PostgreSQL/OSS/Qwen, formal signing, TalkBack and cohort metrics remain NO-GO inputs rather than claims of completion.

## Round 6 local adjudication

- **API 34 execution evidence: partially closed.** The official Android 14 AVD now runs all three instrumentation tests with zero failures, errors or skips. A separate APK smoke gate proves onboarding, the system permission dialog, denied/full/partial UI states, native partial-photo selection and an empty crash buffer. This does not replace physical Huawei/Xiaomi/OPPO/vivo evidence.
- **Share intent without explicit consent (P1-2): fixed.** `MainActivity` no longer consumes external `ACTION_SEND` data. The only exported share receiver accepts at most 20 `content://` images and shows an in-app disclosure with explicit cancel or “import and analyze”; copying and scheduling occur only after confirmation. The APK smoke gate asserts this confirmation surface.
- **External URI TOCTOU (P1-3): rejected for the post-consent pipeline.** Picker/share URIs are copied once into app-private storage before analysis. Sanitization, the final privacy pass and upload operate on private bytes; MediaStore candidates separately re-open the exact protected URI at critical boundaries.
- **JPEG alternate output paths (P1-4): rejected for production upload.** The only production `Bitmap.compress` call is in `ImageSanitizer`, immediately followed by structural stripping and validation; `RemoteAnalysisClient` uploads only the returned sanitized byte array. The other compress call is an instrumentation-test fixture.
- **Anonymous reinstall budget reset (P1-5): aggregate spend fixed, attribution intentionally absent.** Per-device attribution still resets because persistent hardware fingerprinting would weaken the privacy model. An independent timestamp-only global ledger survives device deletion, and atomic global day/month fuses cap aggregate spend; tests cover delete/reinstall and cross-device use. Real PostgreSQL load and cloud-account quotas remain external.
- **URL, model allowlist and unique-work findings (P1-6/P1-8/P1-9): rejected as already controlled.** The server creates upload targets, client redirects are disabled and exact scheme/host/port/userinfo rules are tested; writer fact/source IDs are compared to the selected reviewed allowlist; WorkManager uses unique work and the server has a unique per-device candidate key.
- **Crash-before-finally object residue (P1-7): accepted and mitigated, cloud proof pending.** A process kill can bypass `finally`; the independent five-minute purge and mandatory one-day OSS lifecycle are the intended recovery layers. Real OSS fault injection remains required.
- **Daily switch clock rollback (P1-10): accepted as non-security Beta residual.** Local time can reset the two-switch UX limit. It cannot create facts or bypass server candidate budgets; server-time enforcement can be added if Beta data shows abuse.

## Round 7 local adjudication

- **Permission revocation versus explicit imports (P0-5): scope corrected.** Revoking broad MediaStore permission immediately excludes automatic MediaStore candidates. Picker and share imports are intentionally separate item-level consent paths and must continue to work when broad permission is denied; otherwise the documented fallback would be impossible. “Too private” deletes the private copy and writes local/server suppression. `pause analysis` cancels unique work, and the same-origin upload call is coroutine-cancellable so WorkManager cancellation propagates to the in-flight request. Mid-flight fault injection remains a device evidence item.
- **MediaStore provider replacement (P0-6): rejected.** `ImageSanitizer` reads the protected URI once to produce a private byte array. ML Kit then performs the final privacy analysis on that exact byte array, and `RemoteAnalysisClient` uploads the same array without reopening the source. A provider change before sanitization is reflected in the final privacy pass; a change afterward cannot affect upload bytes.
- **Retry duplication (P0-7): rejected for identity, cloud fault proof pending.** A candidate keeps one token, the database has a unique device/candidate key, and retries query the existing job before upload. OSS keys derive from that job, so a retry replaces the same object rather than creating a second candidate. Timeout and process-kill behavior still belongs in real OSS fault injection.
- **JPEG contradiction and source formats (P0-9/P1-7): rejected.** The guard can defensively accept an exact standard JFIF APP0 with no thumbnail, but the production stripper removes APP0-APP15 and COM before the guard runs. It also requires exact EOI and parses markers between scans, so post-EOI and inter-scan metadata fail. The invariant is on freshly encoded output bytes and is independent of whether the decoded source was JPEG, PNG, HEIF or WebP.
- **Fact/source, URL and bearer findings (P0-10/P0-11/P0-12): rejected as Kimi visibility limits.** Local tests cover strict writer allowlists, URL variants, token rotation and Keystore invalidation. App backup is disabled. Hardware-backed Keystore cannot be required on every supported Android device, so the production invariant is non-exportable Android Keystore encryption with fail-closed key invalidation.
- **Share small-screen overflow (P0-14/P1-9): reduced to external accessibility proof.** The native alert shows only a numeric image count, not 20 previews, and Android supplies a scrollable content panel plus separate buttons. Reference-AVD smoke passes; maximum font, 320dp and TalkBack remain in the physical/accessibility matrix.
- **R8 runtime evidence (P1-6): partially closed.** The latest R8 Release was signed with the local debug certificate solely for testing, installed on API 34, and passed the same onboarding, permission, share-consent and crash-buffer smoke gate. Formal signing and OEM execution remain external.
- **Private-import lifetime (P1-2): fixed with bounded retention.** Sensitive, low-quality and non-retryable imports delete immediately. Completed cards replace the raw copy with the exact sanitized upload bytes; raw pending copies expire after 24 hours, sanitized thumbnails after 30 days, and clearing the index deletes all. API 34 executes replacement, explicit deletion and TTL purge.

## Rounds 8-10 local adjudication

- **Launcher and small-screen evidence: locally closed.** Reusable gates prove 320dp/2.0x onboarding/share controls and a real Pixel Launcher Pin Widget preview, binding-count increase and rendered empty state. TalkBack service focus traversal passes; spoken-output human review and Chinese OEM launchers remain external.
- **Global budget race/reset: fixed in code.** PostgreSQL budget decisions run under one transaction-scoped advisory lock and append an identifier-free budget event atomically with job creation. Device deletion cannot erase aggregate spend history. Real distributed Postgres load remains external.
- **JPEG policy contradiction: rejected after targeted expansion.** Production always strips APP0-APP15 and COM before the final guard. The guard's exact thumbnail-free JFIF acceptance is defense in depth only. Tests now cover APP0, APP13, COM, post-SOS COM, trailing data and a deterministic 512-input malformed corpus.
- **Imported provider retention/DoS: fixed.** Private full copies are terminally deleted or replaced with sanitized bytes and bounded by TTL. Exported-provider reads fail closed at 25 MiB per item, 100 MiB per batch and zero bytes, deleting partial files.
- **Mid-PUT MediaStore revocation: fixed in code, device fault proof pending.** The request body checks exact URI access before each 64 KiB chunk and after the last chunk; a unit test proves revocation interrupts the stream. OSS partial-request behavior still belongs in real-cloud testing.
- **Broad permission versus explicit Picker/share consent: product scope, not a defect.** Broad permission governs automatic MediaStore discovery. Picker/share requires an explicit in-app per-item confirmation and intentionally remains usable when broad access is denied. Users can pause all work, clear the local index, or mark an item private.
- **“Never analyze” cannot undo a prior consent (round-10 P0-5): rejected as temporally impossible.** This action is offered after a card exists, so it guarantees suppression, local/server deletion and no future analysis. It cannot truthfully guarantee that the already-consented analysis never occurred.
- **Remaining P0/P1 evidence:** accepted as release blockers where applicable. Authorized privacy/recognition data, 200 reviewed topics, hosted PostgreSQL plus real OSS/Qwen/HTTPS, formal signing, Huawei/Xiaomi/OPPO-or-vivo, human TalkBack, distributed load and real cohorts remain NO-GO.

## Round 11 local adjudication

- **Content readiness: accepted as the primary release blocker.** Production Beta.62 now structurally contains all 200 controlled topics and 624 facts; 176 topics have three facts and 24 have four, with no empty proposals or incomplete topics. This closes the taxonomy breadth and per-topic count gap, not the semantic-review gate: zero facts have accountable human attestations and zero topics are release-ready. A read-only queue presents all 624 facts with source reachability evidence while granting no approval authority. Pending templates preconfirm nothing; applying decisions pins catalog/fact SHA-256, requires every source on approval, rejects AI identities and stale snapshots, and replaces the catalog atomically. The old direct single-fact writer is disabled. Kimi's suggested smaller interim topic count was rejected because it weakens the product's explicit Beta criterion.
- **Unscoped “never analyze” promise: fixed.** UI and privacy documentation now say “本次安装不再分析”. The Room/server tombstones prevent future processing for the current anonymous installation; uninstall or app-data clearing can reset local identity, and the product does not use a stable hardware fingerprint or claim cross-install recognition.
- **Anonymous reinstall budget reset: accepted privacy tradeoff, globally bounded.** Per-install identity can reset. The identifier-free PostgreSQL global event ledger, registration IP limiter, controlled APK distribution and cloud-account quota are the aggregate controls; claiming persistent per-person attribution would contradict the anonymous design.
- **Exact upload payload identity: fixed and tested.** The client hashes the sanitized bytes after the final privacy pass, before requesting/uploading and after upload. Any in-memory mutation fails closed, and the request body receives the same byte array.
- **HTTP 410 retry loop: fixed and tested.** Suppressed/expired candidates are terminal; 409, 429 and 503 remain bounded retry cases. A 429 keeps the candidate local and publishes a persistent, visible analysis-status message.
- **Share input ambiguity: fixed and tested.** The exported receiver accepts only `ACTION_SEND`/`ACTION_SEND_MULTIPLE`, declared `image/*`, 1–20 distinct `content://` URIs, and rejects a provider-resolved non-image MIME before showing consent. The smoke fixture uses a real MediaStore image.
- **Privacy-action race after card publication: rejected as temporally impossible.** `TOO_PRIVATE` exists only after a completed card and therefore cannot revoke the analysis that already occurred; it deletes local/server artifacts and suppresses future analysis. The UI no longer promises retroactive non-analysis.
- **PostgreSQL execution evidence: locally closed, cloud proof pending.** PostgreSQL 17.10 ran eight migrations twice and eight repository tests across independent pools, including upload-session consumption, lease recovery and feedback preferences; a hosted multi-node deployment, failover, monitoring and cloud fault injection remain external.
- **Release, source and accessibility boundaries: locally hardened, externally blocked.** Debug/Release endpoints are separated; formal Release refuses missing HTTPS/OSS/signing inputs; source guardrails reject placeholders and overpromises. R8 test-signing, 2.0x/320dp, TalkBack service binding/focus and Pixel Launcher pass, but formal signing, spoken-output human review and Chinese OEM launchers remain NO-GO.

## Rounds 12-15 local adjudication

- **China-local scheduling and seven-card policy: fixed and tested.** Server dates now derive from the `Asia/Shanghai` calendar rather than UTC. Tests cover the local-midnight boundary, seven consecutive dates, filling below seven future cards, stopping at seven or 24 uploads, and the two-switch local-day quota. Seven elapsed days on physical OEM hardware remain external.
- **Share disclosure: fixed.** The confirmation now states that image pixels may upload, metadata is removed, processing deletes the copy, and exceptional retention is at most 24 hours. The longer text passes 320dp/2.0x and R8 UI smoke.
- **MediaStore upload contradiction: rejected after executable proof.** Reopening the original descriptor only forces Android to re-evaluate access; the request body never reads it. Multi-chunk tests prove the network body is byte-for-byte and SHA-256 identical to the sanitized bytes while permission checks independently gate progress.
- **Bearer and upload-target boundary: fixed and tested.** OSS requests carry no Authorization header. API same-origin requests only allow the exact base prefix plus `/v1/analysis-jobs/{UUID}/image`, with no query/fragment; admin paths, non-UUID paths and traversal are rejected.
- **Model fact/source invention: fixed and end-to-end tested.** Malicious writers returning forged fact or source IDs receive 502; no card is stored and the temporary object is deleted.
- **Server trust in client privacy flags: fixed in code, real-quality proof pending.** A strict server-side vision result independently flags face, selfie, identity document, bank card, receipt, document, high text density and screenshot. A match rejects before fact/writer use and deletes the object. Tests cover an empty client flag list, provider inspection, structured flags and unknown-flag failure; real Qwen false-negative rates remain an authorized-data gate.
- **Pause coverage: rejected as inaccurate.** `cancelAll()` cancels the initial, imported, periodic and daily-pipeline unique work names, so explicit Picker/share work is included.
- **Round 15 plateau:** no new locally reproducible P0 remained. Kimi correctly retained `NO-GO` for human-reviewed content, authorized evaluation data, real cloud, formal signing, OEM devices, human TalkBack and cohort evidence.

## Post-review local hardening (not a new Kimi round)

- Direct OSS upload was removed. Upload capability is now an authenticated, random, 10-minute API session that PostgreSQL consumes atomically once; API tests reject replay after success, device deletion and anonymous re-registration.
- Processing claims use expiring database leases and conditional terminal writes. Stale workers cannot overwrite a recovered job or publish a second card.
- Card bodies are the exact reviewed fact text; the writer cannot paraphrase a fact into a stronger unsupported claim. Feedback updates bounded topic preferences, is idempotent per action, and is persisted in PostgreSQL.
- Production accepts OSS credentials only with a temporary security token, rejects `Enabled` and `Suspended` bucket versioning, and separates `/health/live` from dependency-aware readiness.
- Fastify was upgraded to 5.8.5 after a live production audit found two High schema-validation advisories in 5.6.2; the current audit reports no known vulnerability. pnpm integrity, Gradle wrapper hashes, dependency verification metadata and module locks now have executable supply-chain gates.
- OpenAPI is the checked Android/backend boundary. The contract gate found and fixed a tracking path-name drift, and feedback now remains queued on every non-2xx or missing-body response instead of being silently discarded.
- Knowledge-source checks distinguish approved release candidates from draft editorial sources. The current catalog reaches 13/13 status-approved candidate and 531/531 total URLs. Real full-catalog and preflight runs exposed machine-unreachable, HTTP-403, HTTP-404, HTTP-429, HTTP-503 and transient transport failures before they could become release evidence. The correction path pins catalog version and SHA-256, preserves draft fact identities, refuses reviewed facts and shared-source mutation, removes orphan sources, and writes atomically. Live evidence supports bounded concurrency and explicit resume of successful checks only when catalog version, source scope and a 24-hour freshness window all match; Beta.62 changed the catalog version and therefore rechecked all 531 sources from zero, with 531 successes and no resume. The release-candidate pass also checked all 13 candidates from zero and passed. The 11 final government sources for the five new safety topics were preflighted by exact URL before ingestion, failed candidates were excluded, and every new safety fact binds at least two official sources. Request timeout, headers, range, content types and two-attempt behavior remain unchanged. The preflight and live-cache boundaries have fail-closed self-tests and CI/source-guard coverage. Publication still requires accountable human semantic review; zero facts currently have that attestation.
- These changes were verified locally; they were not sent as an additional Kimi round. Real cloud, content, data, OEM, signing and cohort evidence remain `NO_GO`.
- Rejected human-review outcomes now have a separate replacement workflow pinned to catalog and fact digests. Replacements remain draft and cannot inherit approval. Generated-card audits compile a de-identified PostgreSQL snapshot with a separate human audit by exact card digest; negative outcomes are retained.
- The final Beta gate now invokes the live knowledge-readiness assessment and requires a formally signed, certificate-pinned release APK plus accountable physical-device `zh-CN` TalkBack listening evidence. The release verifier rejects the existing test-only APK as a negative control. These are local controls, not a 17th Kimi round or release evidence.
- Beta cohort metrics now compile the complete app-exported report set against a human-owned, SHA-bound manifest with seven-day observation; the final gate rejects cross-version evidence. A controlled real-cloud verifier now exercises HTTPS/Qwen/OSS with authorized safe/sensitive fixtures and emits only hashes and checks. Both remain local hardening until real cohort/cloud evidence exists.
- Loop Engineer is vendored at upstream commit `4b9915415e9fcbecab36b2fbd77b59c4a3ebbb7a`. The Kimi path now has hard round/output/total-token caps, SAFE_PACKET-only transport and an explicit external-send checkpoint. The attempted round 17 was not sent because the external-disclosure approval was rejected; 16 remains the actual completed count.
- The latest local critic findings were closed without claiming a new external Kimi round: final evidence now has an Ed25519 trust root; stale-token device deletion preserves recovery and only reclaims the same installation/device binding; `TOO_PRIVATE` is transactionally idempotent; destructive deletion requires confirmation; ML Kit resources and transient failures are handled explicitly; and cloud evidence now binds the exact Dockerfile-backed backend identity plus the deployed OCI image digest. Real release inputs remain `NO_GO`.

## Release interpretation

Safe-packet Kimi reviews cannot produce source-level `GO`, because withholding source is a deliberate
privacy boundary. They remain useful for generating attack hypotheses. Final Beta release authority
comes from the repository checks plus `scripts/check-beta-readiness.mjs` with real, authorized raw
evidence. The empty template must continue to return `NO_GO`.
