# 托管服务升级演练：旧数据兼容与真实运行环境

## 结果与范围

修复一个真实升级缺陷：新版服务连接迁移仅到 0007 的 D1 时，原先仍把 `/health/ready` 报为 200。新版出卡依赖 0008 的预留字段和 0009 的逐模型记录，这个“就绪”是假阳性。

现在就绪检查只读检查产品实际用到的表和列；缺失结构或数据库不可用时返回 503。`/health/live` 不查询数据库，仍可报告进程存活。探针不迁移、不修表、不读取用户数据行、不触发模型。托管产品最低需要 0009；0010 是隔离评测账本，不能要求所有产品用户初始化评测预算。

这是**本地代码与升级兼容性验证**，不是已部署、真实 AI 趣味/事实质量、手机新卡或上架证明。BYOK 的不强制搜索、不额外付费审核、不回退平台 Key 规则没有变化。

## 本次实际验证

`cloudflare/gateway/scripts/check-upgrade-worker.mjs` 使用当前 `wrangler.jsonc` 打包真实 `src/index.ts`，在 workerd 和真实本地 D1 实现中运行。没有维护一套测试专用的出卡 API。

全部外部请求在本机拦截：使用合成 JPEG 字节、合成凭证、合成搜索原文与模型判断；未知目标立即失败，没有网络透传。合成评分不是质量评测结果。数据库仅在独立临时目录，结束后删除本次临时产物。

已通过：

1. 按现有迁移 0001–0007 建库，放入已有设备、额度、完成结果、未结束请求和旧知识。
2. 依次升级 0008、0009、0010；设备、旧知识和既存额度逐字段不变。
3. 就绪检测：0007/0008 返回 503；0009/0010 返回 200。每一步存活检测均 200。
4. 旧完成请求直接重放原结果，0 模型调用；旧待处理请求迁移后保留“可能已经计费”的标记，不退还未知额度。
5. 实际照片接口完成识别 → 内置搜索 → 读取证据 → 写卡 → 三项审核 → 写入缓存，共 6 次合成模型请求、1 次合成网页读取。
6. 同一请求再次调用，返回相同卡和结果，模型记录及额度不变。
7. 模拟上游 HTTP 503，服务返回可重试的 502 `vision_provider_error`，不存成终态成功；未知 Token 保留 NULL，不冒充 0。
8. 同一候选恢复后可通过新缓存出卡；历史未知请求和本次已发送失败请求均不退额度。
9. 实际每日选卡接口使用服务器已发出的两条候选，由合成 AI 选第二条；重放不再调用模型，选卡计数与照片额度分离。

另补充回归覆盖：缺少不同字段/表和数据库故障时就绪检测失败，但存活检测不依赖数据库。原有 Apple 权限运行环境测试改用完整项目迁移，防止只建一个设备表却把服务误认为就绪。

## 线上只读复核

本轮重新查询确认（不是沿用历史结果）：

- 100% 生产版本仍为 `0500e193-595a-4acb-854d-cd1b03db2862`，部署时间 2026-09-04T18:32:34Z。
- 生产 D1 迁移仍只有 0001–0007，查询 `rows_read: 7`、`rows_written: 0`、`changed_db: false`。
- 公开 `/health/ready` 仍返回旧版的 `ok: true`，没有当前源码的 release 字段。

因此不能仅推送新 Worker：应先核对旧 Worker 与新增表/列兼容性及并行请求行为，再在明确发布范围内先应用数据迁移、后切换已验证版本，并验证实际版本与就绪状态。迁移流程遵循 [Cloudflare 官方迁移说明](https://developers.cloudflare.com/d1/reference/migrations/)；本机演练用同一 SQL 文件和 Wrangler SQL 解析器，但没有实际执行远端迁移命令，不等同远端发布回滚演练。

- 下一项产品疑点：托管返回的 `factId` 使用随机卡片 ID，缓存命中同一事实也会得到不同标识；客户端历史去重主要依赖 `factID`。需用真实仓库路径复现重复知识后修复，不能只保证接口能返回卡。
- 真实内容产出/趣味/事实支持、历史未来失败记录恢复、受预算约束的真人照片出卡、离 Mac/蜂窝/跨日组件、购买及正式分发仍待验证。本轮不宣称“完美”或“可上线”。
